# Repair of the stopped resolver

Implemented after the owner asked who would fix the failed release. The repair is now deployed in revision 4, with all four contracts finalized and source hashes verified against the local files and manifest. Real Apple YES, Nintendo NO and no-evidence default NO rulings passed with finalized callbacks and matching reads; the subjective claim was rejected. After the owner approved two additional simulated wei, the new matched ruling finalized MAJORITY_DISAGREE. Its leader proposed a valid NO, but no ruling was accepted. Settlement and claims remain unproven, and chain writes stopped. Revision 3's addresses and failed receipts remain unchanged in deploy/releases/v3-proof.json; its two-wei matched bet remains on its original escrow.

Observed failures were `quote missing from fetched evidence` and `invalid resolution schema`. Receipts expose those validation errors, not the rejected raw model answers. Tests therefore reproduce the failure classes; they do not claim to replay an unavailable exact model response.

The parser now selects and validates required verdict, quotes and reason fields instead of rejecting an otherwise valid answer because it contains unused metadata. Extra fields, including payouts, outcomes and resolution cases, never enter contract state. JSON strings and an exact JSON code fence are accepted; missing required fields, invalid verdicts, invalid indices, overlong reasons and invented quotes still fail.

One bounded correction is allowed inside each nondeterministic judgment. It receives the same frozen rule and fetched documents with an explicit instruction to copy contiguous exact passages. It does not receive the invalid answer as instructions. A second invalid answer raises an LLM error. There is no new transaction, automatic resubmission, guessed ruling, default or technical VOID caused by malformed model output.

Each validator independently performs the same bounded judgment. It must still agree on verdict and resolution case and find every leader quotation verbatim in its own fetched evidence. No fuzzy matching, fabricated date, stitched quote or paraphrase is accepted. The existing fairness cases and refund accounting are unchanged.

Validation: **69 direct contract tests and 21 release tests passed**, including 19 model-output regression cases and the explicit deposit-limit extension guard. All four contracts passed GenVM lint with the pinned runner. Full-validator tests demonstrate that a repaired leader answer is rejected when the independently repaired validator chooses another verdict. Existing exact-quote, mocked HTTP 401/403, timeout, default, conservation and duplicate-refund tests continue to pass.

The deployed repair passed real Apple YES, Nintendo NO and no-evidence default proofs. It did not prevent a later semantic consensus disagreement on the matched Grammy case. Individual validator reasons are not exposed, so the cause is unproven. The cumulative 22-wei deposit budget is exhausted; the new escrow retains two wei. No new production deployment, push or Portal submission followed the failure. See [VERIFICATION.md](VERIFICATION.md) for the stopped run and native balance readbacks.
