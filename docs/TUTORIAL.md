# From a hot take to an auditable receipt

Called It separates a human claim from the money riding on it. That separation starts in `contracts/takes.py`. A user submits one sentence, a category, a future deadline, an integer stake in wei, an integer ratio from one to four, and a default of NO or VOID. The compilation transaction carries zero GEN. The contract checks the stake and date bounds before making a nondeterministic call. Live takes receive their as-of timestamp from `gl.message_raw['datetime']`; participants cannot choose a favourable past starting point.

The compiler's model task is deliberately narrow. It either produces one precise proposition or one rejection classification. Subjectivity, excluded topics, compound conditions and absent evidence paths are grounds for rejection. The response must have exactly the decision, proposition and reason fields. A validator independently compiles the same take. For an accepted claim, it also checks that the proposed canonical proposition preserves the original claim rather than substituting an easier one. The code supplies the evidence standard, disallowed rumours, exact dates, permitted domains and default. Those fields never come from a model's invented monetary decision.

The rule is serialized with sorted keys and compact separators, then SHA-256 hashed. The take initially enters COMPILING. A self-message emitted with `on='finalized'` publishes COMPILED or REJECTED only after its parent judgment finalizes. This is why the app asks you to review a completed rule instead of pretending a form preview is the contract's decision. Open a take's receipt and compare the proposition, event window, default, source domains and hash before funding.

Funding lives in `contracts/take_escrow.py`, which contains no model prompt. The author first calls `prepare_open` with zero value. It reads the compiled take and ensures that resolution has not started. The actual payable `deposit` then uses only escrow-local state: sender, expected amount, reservation deadline and prior deposits. A wrong amount, stale reservation, unknown take or repeated payment is accounted for as refund credit rather than thrown away through a normal assertion failure. A failed execution before the body completes has a separate receipt-verified recovery route.

After the author's deposit finalizes, the escrow becomes OPEN. A different wallet calls `prepare_accept`, reserving the single opposing slot for up to fifteen minutes. That wallet deposits the counter stake, calculated as author stake multiplied by the frozen ratio. A ratio of one means equal stakes. At four, the author stakes two wei and the counterparty stakes eight wei; the winner receives all ten wei. No model computes this arithmetic. Reservations can expire, unaccepted stakes can be refunded after the acceptance deadline, and unresolved matched bets have a later refund deadline.

Evidence enters `contracts/take_resolver.py` after the event deadline. Each participant may register up to two unique URLs. There are only two accepted forms: an exact fourteen-digit Internet Archive `id_` snapshot or an English Wikipedia `oldid` revision. The archive's original host must appear in the frozen category allowlist. CDX must list the exact requested capture. A Wikipedia revision is checked against MediaWiki revision metadata rather than a party-supplied date. Both capture forms must fall after as-of and no later than the event deadline plus seventy-two hours.

Fetching is not the same as trusting. The resolver removes script, style and navigation material, extracts the main content, bounds response size and limits the model input. Party arguments and fetched pages are explicitly untrusted. The model must decide YES, NO or INSUFFICIENT_EVIDENCE against the frozen rule, including the published event date. A rumour about talks cannot satisfy an official-announcement requirement. A clearly dated official announcement can. The leader must supply verbatim decisive quotations. Each validator fetches its own copies, reaches its own verdict and checks every leader quotation against those copies. Merely agreeing on a label is insufficient.

Revision 5 uses the v2 judge's ordered four-step decision and supplies archive capture timestamps explicitly. A completed qualifying announcement can establish YES. A source that only schedules the exact event for a named date in the window, without establishing completion, is insufficient evidence and produces VOID. Documented nonqualifying or unnamed/unannounced reports can establish NO; generic development intentions do not trigger the specific scheduling exception. The Grammy replay demonstrates the scheduling VOID.

Both parties can seal their evidence to request an early ruling after the event window closes. Otherwise the submission deadline protects the other party's opportunity to respond. No evidence produces a deterministic default. Readable but insufficient evidence now resolves VOID. If all submitted source fetches fail, VOID_SOURCES_UNREACHABLE refunds both stakes; after 48 hours without finalized consensus, VOID_TIMEOUT does the same. Only DEFAULT_NO_EVIDENCE applies the frozen default. The app labels default application separately so a default NO never masquerades as an affirmative model finding. A resolver timeout returns VOID rather than paying a default side; escrow also maintains an independent refund deadline.

Settlement reads only a FINAL resolution with the matching rule hash. A finalized self-callback makes the payout available. The winning wallet pulls it with `claim`; native value is emitted only after the parent claim finalizes. The child transfer has its own transaction hash. `verify_claim` binds the parent calldata, wallet, amount, attempt number and child relationship, and checks actual native credit. A failed transfer can be retried only after that evidence is verified, preventing duplicate payout attempts while a transfer is merely slow.

Finally, `contracts/called_it_record.py` reads a finalized matched settlement and derives both players' results. It tracks wins, losses, voids, signed current streaks and category counts. A pending result or an unfunded judgment cannot add a public win. Record insertion is idempotent and its callback is self-only. Historical entries remain visibly labelled.

To reproduce the release, install the pinned dependencies, deploy the contracts, run compilation, obtain the owner's small demo deposit approval, fund, submit the immutable evidence and resolve. `npm run settle` resumes settlement and native claims without replacing saved hashes. `npm run verify:proof` independently reads deployed sources, receipts and state and checks real explorer API objects. It performs no writes and requires no wallet keys. Read the generated release report for exactly which operations have finalized and which checks actually ran.
